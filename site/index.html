The dashboard

Run it, steer it and see it, from one page.

A page on your own computer opens by itself when you start a project. You can watch the work, but you can also drive it: pick what to use, paste your idea, choose the model, see what is being built and have Claude test it in Chrome. Everything below is a screenshot of the real page, not a mock-up.

Chat with Claude, with the model and effort you choose

Start the dashboard with hyperskill.py live --allow-run and the chat box runs Claude on your project, with your own login. Pick the model and effort like in Claude chat, or leave it on Suggested for this phase: research, plan and harden lean on Opus at high effort, build and launch on Sonnet at medium, and each suggestion says why. Edits-only is the default; shell commands are a per-message choice, there is a spend limit and a Stop button, and no mode skips permission checks.

Attach requirements (markdown, text, Word, PDF, CSV, images) or paste your whole brief. Your words decide what is built; HyperSkill decides how, and anything it would change comes back as a question for you.

See what is being built, and have it tested

A running dev server is found on its own, or you add a local address or a project file. It shows in a sandboxed frame at full, tablet or phone width. Check and debug in Chrome gives that run the Chrome DevTools tools: open the app, click through it, read console errors and failed requests, fix the code and test again. In a real run, a small model found and fixed two bugs in a test page in about a minute for about two cents.

Helper agents, split by difficulty

When a phase has several separate pieces of work, it is split into tasks and each goes to the cheapest helper that can do it well: lookups and tiny edits to Haiku at low effort, ordinary coding to Sonnet at medium, harder coding to Sonnet at high effort, hard-to-undo decisions and risky code to Opus. Every tier's model and effort can be changed per project, so a low-cost project can run the architect on Sonnet. The rule is plain arithmetic, so you can see why each task landed where it did. Tasks that touch different files run at the same time; a task that fails moves up a tier. Security, money and data work never goes to the cheap tiers.

In a real run, three helpers ran together in one message: a Haiku scout, a Haiku fixer and a Sonnet builder, for about 37 cents in total. The conductor checked each result itself before recording it.

Which skill, when, and why

Every phase has a plan: which skills are core, which only apply in some situations, which are optional, when to use each and why. Claude pulls a skill only when its moment comes, records why, and releases it at the end of the phase. Anything that is not already in the project needs your OK, and you can override any line from here.

Skill packs

skill packs, bundled and off until you enable them.

The skills are copied unmodified from their authors, with their licences, so nothing is fetched at run time. integrations enable installs one into your project for the phases that use it and it is released when the phase ends. Karpathy’s coding rules are on by default.

  • Sitewright heroes, sign-in backgrounds, components, figures, effects, presets
  • Open Code Review Alibaba’s review skill; needs its ocr program, else the built-in review stays
  • Karpathy guidelines fewer overbuilt, careless edits
  • Impeccable, Taste skill, Emil’s skills, UI UX Pro Max design quality, motion and style systems
  • Security audit Cloudflare’s audit workflow
  • Superpowers, Ponytail, SlopMonster plans, TDD and review; smallest change; de-slopped copy
  • HyperFrames, Watch, Better Icons video, video analysis, icons
  • hs-watch, hs-convert, hs-logo our own: read a video, convert a file, design and export a logo and icon set (bundled)
  • Hallmark, Humanizer, Diagram Design anti-slop design rules and a linter; de-AI-ing prose; architecture and flow diagrams

Skill text was read at README level when vetted, not audited line by line, so enabling a pack runs third-party instructions. Some need tools that are not bundled (ffmpeg, npx hyperframes, the ocr program). Licences and commits are in packs/*/NOTICE.md.

Checks that defend themselves

The state file is signed: edit it by hand and every command refuses until you choose to keep the change or restore the last good copy (repair --accept or --restore). Evidence that names a missing file, or a command that cannot fail, is refused. Four checks (go-no-go, system-design-read, architecture-explained, promo-rendered) can only be passed by a person pressing Confirm in the dashboard. Claude cannot edit or read the key files.

Tamper-evident and accident-proof, not a sandbox: a process that already has your shell can do what you can.

A check before every push

scripts/check.sh runs the whole test suite, the plugin validator, shell and JavaScript syntax and confirms the generated site data is current. scripts/install-git-hooks.sh makes it run before each git push, and the same script runs on GitHub when Actions is available.

Hyperfigure: explain an idea as a working object

/hyperskill-figure builds an interactive isometric figure: a cache key as a pin-tumbler lock, a rate limiter as a turnstile. It has a drawing kit (SVG, WebGL, optional 3D), nine worked examples and audits. Derived from Anatomy by Ryan (MIT); the notice stays with it. Needs Node 20.10+ and Chrome for its checks.

Ten visual styles, with build rules

Skeuomorphism, Neumorphism, Glassmorphism, Claymorphism, Brutalism, Minimalism, Maximalism, Liquid Glass, Bento Grid and Spatial UI. Each has a recipe, its traps and the checks it must pass (style-recipes.md), plus a designed example to play and try live in the dashboard. One style per product: a pick here replaces a pick from the long list.

Helper agents, priced by difficulty

Work is split into tasks and each goes to the cheapest helper that can do it well: Haiku for lookups, Sonnet at medium or high effort for coding, Opus for architecture and review. Tasks that touch the same files never run together, a failed task moves up a tier, and every tier's model and effort can be changed per project from the dashboard to keep a project cheap.

Opt-in tools, not bundled

last30days (what people said in the last 30 days, as evidence, never as proof of demand), Scrapling (bulk public data, within each site’s terms, never to get past bot protection) and REA (analysing a bundle you ship). Each is registered with its risks and does nothing until you ask. Diagram Design, Hallmark and Humanizer are bundled unmodified.

Self-hosted building blocks

GlitchTip (errors), Gotify (alerts), Windmill (automation), Vikunja (tasks), celld and RAG-Anything (questions over your own documents). Each is a tracked check with its licence caveat written next to it and a plain description of what “done” means, including the cost of running it yourself.

Honest about its limits

Tests cover the tracker, registry, hooks, dashboard and site, not model behaviour. Windows and macOS are untested, third-party skill text was read at README level, and the LibreOffice route of hs-convert could not be run in the build sandbox. The full list is under Limits.

How it stays honest

It conducts. It never plays and grades its own work.

  1. Evidence or it did not happen

    gate --pass refuses to record a pass without evidence. gate --run passes only if your command exits 0. advance will not move while any item is open.

  2. Your decisions stay yours

    Stack, tenancy, providers and limits are asked, not assumed, then written to docs/decisions/ so a new session cannot quietly change them.

  3. Fresh eyes review the code

    Security and test-quality reviews run in a read-only reviewer agent that did not write the code. A skill saying “all clear” is input, never the verdict.

  4. Licence-aware by default

    Opt-in tools stay off until you enable them. Tools with noncommercial licences are blocked on commercial projects, and the resolver says why.

Known limits

What it cannot promise.

  • The recorded state is signed and Claude is kept out of its files and keys, so a hand-edit is caught and shown to you. That is tamper-evidence, not a sandbox: an agent with full shell access to your account could still find a way around the hook, and evidence is checked for being real, not for being good.
  • Gates are reported by the model. --run makes many of them machine-checked; items like “the owner read every line” still rely on honesty.
  • The guidance has not yet been dogfooded on a real product end to end. Expect some phases to need trimming.
  • HyperSkill is MIT-licensed. Some of the source material it was written from has no stated licence and the reference text was rewritten, not cleared; read the licensing status in docs/sources.md in the repository.
  • Third-party skills can change under you. Pin versions and read what you install.
