# Structure of a 40-second product explainer

A short explainer is four beats, in this order. Write the beats before any design; if a beat has no sentence, the video is not ready.

| Beat | Seconds | What it does | The test |
|---|---|---|---|
| Intro | 0-5 | Names the product and the one thing it is for, in the viewer's words | Someone muting the video still gets the name and the promise from the first frame |
| Problem | 5-15 | Shows the pain the viewer already has, with a real example, not an adjective | The viewer thinks "that is me" before the product appears |
| Use case | 15-33 | One concrete job done in the product, start to finish, with real screens | Every number and screen is from the real product; nothing invented |
| Call to action | 33-40 | One action, named for what it does, with where to do it | One sentence, one button or address, on screen long enough to read twice |

Rules that follow from it:

- **One use case, not a feature tour.** If you need three features, make three videos.
- **The problem is shown, not claimed.** "Teams waste time" is an adjective; a screen of twelve open tabs is a problem.
- **The pace follows the beats.** The problem can be quick, the use case needs time to be read, and the call to action must hold still.
- **Check it with `hs-watch`** after rendering: read the contact sheet and confirm each beat lands at about its time and that the text is readable at the frame size you will publish at.

The four-beat shape is a common structure for short SaaS explainers; this is our own write-up of it, not a copy of any particular video.
